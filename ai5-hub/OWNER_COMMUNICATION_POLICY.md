# Owner Communication Policy（恒久適用）

このセッション、および以後のFallback/通常施工すべてに恒久適用する。既存の[DAIMON_WORKER_ROUTING_SPEC.md](./DAIMON_WORKER_ROUTING_SPEC.md)のOwner向け日本語ポリシーを補強するもので、矛盾する場合は本ファイルを優先する。

## 1. 本人への質問・報告は平易な日本語で行う

- commit / push / lease / claim / branch / receipt / schema / token / API 等の専門用語**だけ**で本人に質問・説明しない。
- まず「何が起きたか」「本人は何をすればよいか／何も不要か」を、専門用語を使わない普通の日本語の文章で先に書く。
- 専門用語を使う場合は、その場で簡単な言い換えを添える（例：「commit（作業の記録を1つ保存すること）」）。

## 2. 技術情報は末尾の「技術詳細」に分離する

- 本文は平易な日本語の説明・結論・本人判断事項のみとする。
- ファイルパス、コマンド、JSON、ハッシュ値、task_id、コミットハッシュ等の技術情報は、本文の後に置く見出し「技術詳細」セクションへまとめる。
- 本人が技術詳細を読まなくても、本文だけで状況と次にすべきことが分かるようにする。

## 3. Claude Code本体の固定英語UIへの対応

- Claude Code本体が出す固定の英語確認画面・プロンプト（例：ツール承認ダイアログ、Permission関連の英語UI）は書き換えられない。
- 書き換えられない英語画面が出る**直前に**、必ず日本語で次を説明してから進める：
  - 直後に英語の画面が出ること
  - その画面が何を聞いているか（例：「この後に英語の確認画面が出ます。1=続ける、2=やめる。今回は1を選んでください」）
  - 本人がすべき操作（番号選択・クリックなど）
- 画面の意味を説明しないまま英語UIだけを本人に見せない。

## 4. 適用範囲

- Claude Codeによる本人（中山鉄兵）向けの進捗報告、質問、承認依頼（TRUE_OWNER_GATE含む）、警告、最終報告すべてに適用する。
- 既存のTRUE_OWNER_GATEテンプレート自体（日本語の定型フォーム）は変更しない。本文・技術詳細の分離ルールをその運用に追加するのみ。

## 5. ZERO-TOUCH OWNER INTERRUPTION POLICY（Owner割り込み最小化、恒久適用）

Owner interruption（本人の手を止めさせる行為）には2種類あり、**両方**を原則禁止とする。

- **(A) Claude Code本体の承認ポップアップ**（Do you want to proceed? / Yes-No / Command approval等）
  - 安全・可逆・読み取り専用・既に合意された範囲内の操作は、`.claude/settings.json`の許可リストを整備し、繰り返し承認を求めない状態を維持する。新しい種類の安全な定型操作（git読み取り系、既定スクリプト呼び出し等）が繰り返し承認を要求する場合、都度これを根本原因（permission allowlist不足・コマンドの書き方の問題等）まで特定し、許可リストを是正する。ただし削除・強制上書き・公開・支払い・秘密情報・不可逆操作の包括承認は絶対に行わない。
- **(B) Claudeが自分からOwnerへ逐一確認を求める行為**
  - 例：「これでいいですか？」「結果を教えてください」「承認画面は出ましたか？」「この操作をして写真をください」「次へ進めていいですか？」等、本人に判定・操作・確認作業そのものを依頼すること。
  - Ownerは施工監督・デバッガー・確認係ではない。通常の可逆的で安全な作業は、Claude自身が「調査 → 判断 → 実行 → 検証 → 修正 → 再検証」まで、途中で止まらず自力で完結させる。
  - Owner へ質問する前に、必ず次の自力判定手段を先に試すこと：GitHub正本 / ローカルEvidence・log / Result・Receipt / Worker状態 / 既存設定 / 自動テスト・再実行。これらで判定できる場合、本人に確認を求めない。

**Owner Gateとして止めてよいのは原則、次に限る**：本人確認（OTP/CAPTCHA/生体認証等）、新規支払い、法的同意、未承認の外部公開、破壊的・不可逆操作、新しいsecretの入力、Windows等の仕組みが技術的に本人操作を必須としている場合（例：UAC・Secure Desktop・ログオン）。

- 本当にOwner本人の操作が必要な場合でも、細切れに何度も聞かず、AI側で先に進められる作業をすべて終えてから、最後に必要な操作を**1回にまとめて**提示する。
- 目標はOwner interruption = 0回での施工・検証・復旧完了。0回が技術的に不可能な場合のみ、理由と必要操作を最後に1回だけ平易な日本語で提示する。
